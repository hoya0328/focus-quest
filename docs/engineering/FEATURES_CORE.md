# 기능 명세: 집중과 성장

공통 시간 단위: 입력은 분, 화면 남은 시간은 초, `endAt`은 Unix 밀리초, 저장 시각은 ISO 문자열이다. 일/주 통계는 사용 기기의 로컬 날짜 기준이다.

## FQ-01 — 친구 선택·준비·모험 장면

- **흐름:** `select → setup → focus → complete`. 캠프는 별도 `camp` 화면이다. 휴식도 `focus` 화면에서 `mode=break`로 실행한다.
- **선택:** `hike=모리`, `swim=나루`, `fish=보리`. 파일명의 `momo`/`podo`는 이전 에셋 식별자이며 공개 이름과 다르다. 파일명을 일괄 변경하지 않는다.
- **설정:** 집중 1~120분, 휴식 1~30분, 목표 한 줄 최대 80자. 설정 파싱에서 잘못된 값은 유효한 상태로 취급하지 않는다.
- **연출:** React의 진행률·정지·성장 단계를 Phaser가 표현한다. 등산 정상/깃발, 수영 보물상자, 낚시 황금 잉어 사건은 현재 장면 안에서 처리한다. 화면 장식이 완료 기록을 직접 추가하지 않는다.
- **실패/복구:** 장면은 지연 로드되며 준비 UI와 분리한다. 브라우저/기기별 성능은 별도 QA다. 지원되지 않는 전체 화면을 강제하지 않는다.
- **수용:** 키보드로 친구 변경·출발 가능, 390px/태블릿/PC에서 조작부와 장면이 겹쳐 잘리지 않음, 집중/휴식이 같은 아트 기준을 따름.
- **근거:** [화면 조합](../../app/page.tsx), [집중 장면](../../app/components/AdventureQuestScene.tsx), [낚시](../../app/components/FishingQuestScene.tsx), [휴식](../../app/components/RestQuestScene.tsx), [디자인 기준](../../DESIGN.md), [반응형 회귀](../../e2e/responsive.spec.ts).

## FQ-02 — 포모도로·일시정지·복구·여러 세트 원정

| 상태/동작 | 계약 |
| --- | --- |
| 시작 | `startedAt`, `endAt`, 남은 초, 동료/음악/목표/선택 퀘스트를 ActiveSession v1로 저장 |
| 실행 | 250ms UI 갱신은 화면 갱신 주기일 뿐. 실제 시간은 `ceil((endAt-now)/1000)` |
| 정지 | `paused=true`, `endAt=null`, 당시 남은 초 보존 |
| 재개 | 현재 시각 + 남은 초로 새 deadline 설정 |
| 새로고침 | 저장 payload 검증. 만료됐다면 집중 완료를 복원하고 기록 중복 방지 |
| 집중 완료 | 완료 잠금 → 오디오/PiP 종료 → 활성 세션 해제 → 완료 기록/퀘스트 세트 처리 |
| 휴식 완료 | 집중 기록을 새로 추가하지 않음 |
| 중간 원정 세트 | 체크포인트 화면. 최종 목적지 보상과 구분 |
| 최종 원정 세트 | 같은 장면의 성공 연출 후 완료 화면. 현재 연출 대기 4.2초 |

원정의 UI 선택과 데이터 유효 범위를 혼동하지 않는다. 현재 UI는 1/2/3/4세트이고 도메인은 2~8세트 원정을 허용하며 수동 학습 퀘스트의 목표 세트는 1~12다. UI가 적은 선택지만 보여도 저장 파서의 호환 범위를 축소하지 않는다.

완료 ID는 화면 조합에서 `${startedAt}-${adventureId}`로 고정해 복구/RPC 재시도를 중복 완료로 세지 않는다. `createFocusRecord` 단독 기본 ID와 구분한다. 시간 초과 복구와 정상 완료의 timestamp 선택도 유지한다. 장시간 화면 잠금 중 OS가 실행을 멈출 수 있으므로 복귀 시 시간 보정과 OS 종료 알림 보장은 다른 계약이다.

**수용:** 주입한 `now`로 정지·복구 결과가 재현됨, 같은 세션 반복 복구가 기록/세트를 증가시키지 않음, 휴식이 성장 시간을 만들지 않음. [계산](../../lib/pomodoro.ts), [조합](../../app/page.tsx), [규칙 테스트](../../tests/pomodoro.test.mjs), [게스트 E2E](../../e2e/guest.spec.ts), [격리 계정 E2E](../../e2e/staging.spec.ts).

## FQ-03 — BGM·작은 타이머·전체 화면·딴생각 보관

- BGM은 외부 음원 스트리밍이 아닌 Web Audio 합성이다. `forest/waves/lake/quiet`를 구분한다. 세션 종료·컴포넌트 해제 시 AudioContext와 벨 타이머를 정리한다.
- 작은 타이머는 Document Picture-in-Picture 지원 여부를 확인하고, 미지원이면 대체 창/안내 경로를 사용한다. 목표·시간·원정 상태는 동일 React 상태에서 갱신한다. OS 위젯·네이티브 Live Activity가 아니다.
- 딴생각 메모는 해당 브라우저의 LocalStorage에 저장하고 완료 화면에서 다시 볼 수 있다. Camp 채팅이나 제품 집계에 자동 전송하지 않는다.
- **수용:** 음소거/일시정지/완료 시 소리가 남지 않음, 작은 창 닫기가 원본 타이머를 중복 시작하지 않음, 미지원 브라우저에서 시작 자체는 가능.
- **근거:** [구현](../../app/page.tsx), [가상 사용자 회귀](../../tests/virtual-user-qa.test.mjs), [PWA 회귀](../../tests/pwa.test.mjs). 실제 음질·음량과 iOS 정책은 [실기기 항목](LIMITATIONS.md).

## FQ-04 — 기록·Camp Log·중단 후 복귀

- 완료 기록: ID, 시작/완료 시각, 분, 동료, 선택적 목표/퀘스트/원정 정보. 최신 400개를 유지한다.
- Camp Log: `finished/unfinished/split`, 선택형 회상 최대 160자, 자신감 1~5, 난도 `light/steady/heavy`. 회상 저장은 세션 완료와 별개라 생략해도 완주가 사라지지 않는다.
- Recovery Quest: 중단 이후 5/10분 등 더 작은 재출발을 제안한다. 유효기간은 7일이고 만료/손상 데이터는 재사용하지 않는다.
- 주간 기록은 월~일, 연속 집중일은 로컬 날짜로 계산한다. 기록은 학습 이해도·집중 품질의 객관적 증명이 아니다.
- **실패/복구:** 손상된 저장 데이터는 파싱에서 거른다. 로그인이 없으면 브라우저 삭제/다른 기기 이동으로 게스트 기록을 잃을 수 있다.
- **수용:** 회상 저장이 새 완주를 만들지 않음, 자정·주 경계/중복 ID/만료 복귀 퀘스트 회귀 통과.
- **근거:** [기록 규칙](../../lib/pomodoro.ts), [복귀 규칙](../../lib/retention.ts), [회상 패널](../../app/components/CampReflectionPanel.tsx), [주간 기록](../../app/components/WeeklyAdventureLog.tsx), [복귀 테스트](../../tests/retention.test.mjs).

## FQ-05 — 월드·동료 성장·원정 유물·계절

| 체계 | 계산 기준 | 구별할 점 |
| --- | --- | --- |
| 월드 5단계 | 해당 동료의 10분 이상 완주, 10/25/50/100회 경계 | 다른 동료 월드에 합산하지 않음 |
| 첫 흔적 | 같은 유효 완주의 첫 3회 | 고단계 배경 교체와 별개 |
| 동료 4단계 외형 | 해당 동료의 완료 집중 분 누적 | 월드 횟수와 다름. 정확한 경계 숫자는 사용자 UI에 노출하지 않음 |
| 원정 기록 | 유효 완주 100회 이후, 유물 125/175/250/400회 | 동료별로 계산. 숙련 등급은 이후 50회 간격 |
| 계절 사건 | 실행 시각으로 계산하는 계절 | 결제/서버 AI/랜덤 보상 서버 없음 |

동료 성장 원장은 세션 ID로 중복 제거하며 최신 2,000개, 일반 기록은 400개 상한이다. **무제한 누적 영구 원장**이 아니다. 월드·유물은 현재 보유 history에서 재계산하므로 장기 운영에서 상한을 넘기기 전에 서버 누적 원장 설계가 필요하다. 이 작업에서 계산 규칙을 변경하지 않는다.

**수용:** 경계 직전/직후 배경과 외형 일치, 친구 간 성장 독립, 휴식/짧은 세션이 월드 횟수를 올리지 않음. [월드 규칙](../../lib/retention.ts), [외형](../../lib/companion-growth.ts), [배경](../../lib/world-growth.ts), [유물](../../lib/adventure-archive.ts), [계절](../../lib/seasonal-events.ts), [성장 E2E](../../e2e/world-growth.spec.ts).

## FQ-06 — 이메일 계정·클라우드 저장

- 게스트 기록을 첫 로그인에서 병합한다. 기존 소유자 표식이 다른 계정이면 그 로컬 기록을 이관하지 않는다.
- `CloudStateData` v4는 설정·최근 기록·활성 세션·복귀 퀘스트·동료 성장이다. 과목/PDF/퀴즈는 별도 관계형 테이블이며 이 JSON의 하위 컬렉션이 아니다.
- CAS 저장과 직렬 저장 큐로 충돌을 처리한다. 같은 버전을 기대한 수정만 저장하며 충돌 시 최신 상태를 읽어 병합 후 한 번 재시도한다. visible tab은 10초 주기로 확인한다.
- 병합: 설정은 cloud 우선, 기록은 ID 중복 제거, 회상은 `savedAt`, 세션/복귀는 각각 변경시각이 최신인 쪽. 같은 변경시각이면 cloud를 선택한다. 세션 `null`도 유효한 종료 표시다.
- 로그아웃은 마지막 저장이 실패하면 중단하고 오류를 표시한다. 성공 시 계정 소유 캐시를 비워 다음 사용자의 화면으로 노출하지 않는다.
- 이메일 인증/재설정, 선택형 Google OAuth는 제공자 설정에 의존한다. 구현이 외부 이메일 발송 성공을 증명하지 않는다.
- **수용:** A↔B 계정 전환 격리, 첫 게스트 병합, 동시 저장 충돌, 새로고침·오프라인·재접속 보존, 실패 시 로그아웃 중단. [hook](../../app/hooks/useCloudSync.ts), [병합](../../lib/cloud-state.ts), [저장 adapter](../../lib/cloud-sync-backends.ts), [계정 규칙](../../tests/public-auth.test.mjs), [동기화 회귀](../../tests/cloud-state.test.mjs).
