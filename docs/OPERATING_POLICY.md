시간 기준은 보관기한이지 개인정보 삭제 요청을 미루는 유예기간이 아니다. 개인 PC가 꺼지면 백업·만료·과거 사본 정리가 지연될 수 있다. 상시 실행·오프사이트 사본·키 복구 보관이 준비되기 전에는 “24시간 무손실 보장”이나 “완전한 재해 복구”를 안내하지 않는다.

## 백업과 복구

`npm run backup:daily`는 CLI 관리자 자격 증명을 프로세스 메모리로만 받아 앱18개 테이블(확인 기록 포함)·최소 Auth 식별 정보·연결 PDF를 복사한다. DB 행은 단일 읽기 스냅샷이며 PDF 바이트는 후속 다운로드다. 참조 PDF 누락·API 오류·범위 초과는 실패로 처리한다. 스키마는 Git 마이그레이션으로 관리한다. 비밀번호 해시·토큰·세션·MFA·OAuth 제공자 연결은 백업하지 않으므로 Auth 복구 시 본인 확인·비밀번호 재설정·재연결 절차가 필요하다. PostgreSQL 물리 백업·PITR과 다르다.

각 객체와 목록을 AES-256-GCM으로 암호화하고 SHA-256·크기·인증 태그·목록 인증을 검증한다. 키는 Windows CurrentUser DPAPI로 보호한 `backups/.keys/master.dpapi`에 두며 Git에서 제외한다. 다른 OS는 외부에서 제공한 보호 키가 없으면 실패한다. 현재 PC/Windows 계정이 손실되면 키를 복구할 별도 보관 수단은 아직 없다. 키를 채팅·소스·GitHub에 복사하지 않는다.

로컬 백업은 매일 생성·검증·보관 정리를 예약한다. 기존 사본과 새 사본의 무결성 검증이 끝난 뒤에만 생성 후30일 지난 사본 및 삭제 요청 정보가 포함된 사본을 폐기한다. PC·Codex·기존 인증에 의존하므로 실행이 지연될 수 있다. 기본 수동 백업 명령은 생성 전용이다. 검증 실패 시 삭제나 처리 완료로 보고하지 않는다.

동시 실행은 전용 잠금으로 차단한다. 사본에 누락·목록 외 파일·손상이 있으면 전체 삭제 계획을 중단한다. 기존 암호화 사본이 있는데 보호 키가 사라진 경우 새 키로 대체하지 않는다.

운영 복원은 자동화하지 않는다. 먼저 현재 삭제 대장을 확인하고 사본 정리를 완료한다. 최신 검증 사본을 격리 Supabase에 복호화하고 마이그레이션·계정 식별자·앱 관계·PDF·소유자 접근을 검증한다. 삭제 요청 대상은 복원하지 않는다. 실제 운영 복원은 별도 장애 대응 승인과 인증 재설정·사용자 안내 후 수행한다. 로컬 격리 E2E만 합성 계정·과목·PDF를 삭제/복구하는 훈련을 한다.

## 문의·권리 요청 SOP

1. 메일 도착 시 비밀번호·인증 링크·키·불필요한 원본 자료를 요구하지 않는다. 최소 계정 이메일과 발생 화면·시각·요청 ID로 시작한다.
2. 접수일·요청 종류·최소 식별 정보·처리 기한·상태를 접근 제한된 운영 기록에 남긴다. 공개 GitHub 이슈에는 개인 정보를 옮기지 않는다.
3. 3영업일 내 첫 답변을 목표로 하되 열람·삭제 등 법정 처리기한이 우선한다. 추가 확인은 필요한 최소 범위에서 한다.
4. 삭제는 운영 계정/자료와 과거 사본을 각각 확인한다. 승인된 정리 모드 `npm run backup:daily -- --apply-retention` 이후 관리자 상태의 미처리 백업 삭제 건수가0인지 확인한다. 기본 생성 전용 명령만으로 사본 삭제를 완료 처리하지 않는다. PC 지연·실패는 완료로 안내하지 않는다.
5. 완료일을 표시하고90일 후 메일·첨부·운영 기록을 수동 정리한다. 월1회 처리 완료 폴더를 검토한다. 법적 보존 사유가 있으면 근거·기간·범위를 따로 기록하고 해당 이용자에게 설명한다.
6. 법정 권리, 국외 처리/위탁의 적법 근거, 법정 보존 예외는 전문 법률 검토가 필요하다. 문서와 코드 점검은 법률 적합성 인증이 아니다.

## 공개 전 사람이 확인할 경계

- R2 활성화 화면이 결제수단·계약·과금 승인을 요구하면 진행하지 않는다. 무료 사용량은 결제수단 없는 가입을 보장하지 않는다.
- 상시 실행 외부 사본과 키의 별도 안전 보관, PC 꺼짐 감지·복구 목표는 미완료다.
- 실제 iOS/Android 알림·오디오·백그라운드, 문의 메일 수신·회신, 법률 검토와 실사용자 연구는 사람이 확인한다.
- 비용 상한은 사업자 대시보드에서 실제 플랜·사용량으로 확인한다. PDF 한도는 남용 완화이며 계정 전체 요금의 하드캡이 아니다. 유료 AI·결제는 활성화하지 않는다.

현재 기술 절차는 [운영 런북](OPERATIONS_RUNBOOK.md), 인수 기준은 [기술 명세](engineering/README.md)를 따른다. 실제 실행·승인 근거는 비공개 운영 기록으로 관리하고 날짜별 과거 보고서를 현재 검증으로 간주하지 않는다.
