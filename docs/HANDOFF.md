- Diagnosis: the bucket, PDF MIME limit, and Storage policies existed, while the object key still included the original Unicode file name.
- Repair: uploads now use `<user UUID>/<material UUID>/source.pdf`; the original name remains available in the database and UI.
- Recovery: Storage authentication, policy, bucket, and status failures now produce distinct user-facing guidance.
- UX: the error status has a stable heading and no longer repeats the same generic sentence.
- Analysis save repair: sanitize NUL characters and stop requiring a full returned row after a successful update.
- Focused validation: 9 PDF/quest tests, TypeScript, and changed-file ESLint passed.

- 모바일에서는 각 친구를 가로형 카드로 바꾸고 선택한 친구의 준비 버튼을 전체 너비로 표시한다.

### 검증

- TypeScript 검사 및 변경 파일 ESLint 통과
- Vinext 운영 빌드 통과
- 인앱 브라우저 접근성 트리에서 세 친구의 라디오 선택 상태와 `모리와 준비하기` 진입 버튼을 확인했다.
- 브라우저 스크린샷 연결은 디버거 단계에서 시간 초과되어 자동 이미지 캡처는 남기지 못했다.

### 참고

- 로컬 미리보기는 `http://127.0.0.1:5182/`이며 배포하지 않았다.

## 2026-11-13 — P0 운영 백엔드와 보안 경계

### 완료

- 일시 중지됐던 Supabase `Focus Quest` 프로젝트를 기존 데이터와 프로젝트 ID를 유지한 채 복구했다.
- 계정 동기화, 과목·퀘스트·PDF, 학습 진척, 퀴즈 시도와 최소 제품 이벤트를 다섯 개의 버전 관리된 마이그레이션으로 운영 DB에 적용했다.
- 익명 역할은 모든 개인 테이블에서 차단되고, PDF 버킷은 사용자 UUID 경로만 허용한다.
- 직접 호출 가능했던 `rls_auto_enable()` 이벤트 함수의 외부 실행 권한을 회수했다.
- 계정 삭제는 본인 Supabase 토큰과 정확한 확인 문구를 검증한 뒤 PDF와 Auth 계정을 순서대로 삭제하도록 구현했다.
- 전체 린트·타입 검사, 운영 빌드, 로직·PDF·퀘스트·서버 렌더링 테스트와 의존성 감사를 통과했다.

### 운영 연결

- Cloudflare 공개 설정에는 `SUPABASE_URL`만 기록한다.
- `SUPABASE_SERVICE_ROLE_KEY`는 Git이나 `.env`가 아니라 Worker의 암호화된 Secret에만 둔다.
- 배포 후 `npm run security:anonymous`를 다시 실행해 위조 헤더, 익명 계정 삭제, RLS와 Storage 경계를 확인한다.
- 상세 근거와 의도적으로 실행하지 않은 파괴적 검사는 `docs/SECURITY_AUDIT_2026-11-13.md`를 따른다.
