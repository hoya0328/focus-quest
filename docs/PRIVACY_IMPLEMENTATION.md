# 개인정보 안내와 가입 확인

시행 버전: `2026-11-25` · 공개 경로: `/privacy`

## 확정된 정보

- 사용자 확인에 따라 개인정보 보호 담당자는 조병호(활동명 HOYA), 연락처는 `letshoya@naver.com`으로 표시한다.
- 운영 Supabase 메타데이터 조회 결과 주 리전은 `ap-northeast-2`(서울)다. 호스팅·로그·지원·하위 처리업체까지 모두 국내 처리라고 해석하지 않는다.
- 만 14세 이상만 회원가입을 제공하며 생년월일·실명·전화번호를 가입 항목으로 추가하지 않는다.

## 화면·데이터 계약

- 가입 화면과 홈 푸터에서 방침을 새 탭으로 연다. 로그인 없이 읽을 수 있고 목차·키보드 포커스·홈 복귀·문의 링크를 제공한다.
- 새 이메일 가입에 연령 자기 확인과 방침 확인을 각각 요구한다. 기본 선택하지 않으며 창 닫기·모드 전환·이메일 변경 시 초기화한다. 창을 닫으면 입력한 이메일·비밀번호도 메모리 상태에서 지운다.
- Auth 사용자 메타데이터에 `age_over_14_declared`, `privacy_notice_version`, `privacy_notice_acknowledged_at`만 추가한다. 기존 계정의 과거 확인을 만들어 넣지 않으며 기존 이메일 로그인·게스트 사용은 바꾸지 않는다.
- 메타데이터는 이용자가 수정할 수 있다. 신원·생년월일 검증, 변경 불가능한 동의 증명, 권한·관리자 판정에 사용하지 않는다. 확인란은 방침 인지·연령 자기 신고이며 광고 동의가 아니다.
- Google 로그인은 기존과 같이 운영에서 비활성이다. 향후 활성화 전에는 제공자 정보·최초 가입 확인 기록을 다시 검토한다.
- 새 DB 테이블·정책·권한 변경이나 기존 사용자 데이터 수정·삭제는 없다.

## 실제 구현과 고지

`useCloudSync`·계정 삭제 API, `useStudyMaterials`·PDF 클라이언트, `useProductTelemetry`, `useSilentCamp`·캠프 스키마, Push API·Worker, 서비스 워커와 백업 스크립트를 확인했다.

자료 삭제, 계정 전체 삭제, 타이머 클라우드 레코드 삭제, 다른 기기의 로컬 데이터 삭제를 같은 동작으로 안내하지 않는다. 계정 식별자에 연결된 이벤트 원본을 익명 통계라고 부르지 않는다. 외부 생성형 AI 전송이 없는 현재 동작과 별도 백업의 삭제 예외를 명시한다.

## 개인정보 문의 대응

1. 요청 범위와 본인·정당한 대리인 여부를 필요한 최소한의 방법으로 확인한다. 비밀번호·인증 코드·인증 링크·PDF 원본을 요구하지 않는다.
2. 앱의 본인 삭제 기능을 우선 안내한다. 확인되지 않은 이메일 요청만으로 다른 사람의 계정을 조회·삭제하지 않는다.
3. 백업 사본·다른 기기의 로컬 데이터·제공자 기술 로그의 범위는 별도 설명한다. 백업 복원 시 이미 처리한 삭제 요청도 다시 반영한다.
4. 처리 결과 또는 제한 사유와 후속 절차를 요청자에게 알린다. 문의 내용·개인정보를 공개 GitHub 이슈에 올리지 않는다.

## 검증과 남은 운영 결정

- 로직: 두 확인란, 최소 메타데이터, 핵심 고지, 안전한 링크와 가입 호출 전 차단.
- 공개 경로 E2E: 푸터 새 탭·원래 화면 유지, 1440·834·390px 넘침과 목차.
- 격리 Supabase E2E: 미확인 가입 차단, 창 재개 초기화, 합성 계정 실제 가입과 확인 메타데이터 조회. 운영 계정·메일·개인 자료는 시험에 쓰지 않는다.
- 전용 문서 CSS 약 2.6KB와 가입 확인 스타일을 위해 전체 클라이언트 CSS 예산을 225KB에서 230KB로 조정한다. 이미지·JS 예산과 기존 구조는 유지한다.
- 현재 없는 백업·문의 메일·이벤트 자동 만료를 있다고 쓰지 않는다. 백업 보존 기간과 수동 삭제의 실운영, 제공자별 국외 처리 범위·근거와 위탁 계약은 정식 운영 전 계속 검토해야 한다.
- 이 작업은 실제 구현을 설명하는 고지와 UI 구현이며 법률 검토·법적 적합성 인증을 대신하지 않는다.
